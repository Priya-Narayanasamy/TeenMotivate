# Changelog

Built in phases. Phases 2-6 were run straight through on request rather than
stopping after each one.

## Phase 6 — polish

- `.streamlit/config.toml` sets the app surfaces to the same colours the charts
  draw on, so a chart no longer reads as a grey box on a white page. Both
  `[theme.light]` and `[theme.dark]` are defined, so the app still follows the
  browser preference.
- `README.md` — screenshots, the data contract, the layout, and the points
  rules. The rules section is generated by `scripts/update_readme.py` from
  `POINTS_CONFIG`, between HTML comment markers, so it cannot drift from the
  engine. Re-running it is a no-op when nothing changed.
- Checked at 390px in a real browser: no horizontal overflow on any page,
  charts reflow, columns stack. Screenshots in `docs/`.

## Phase 5 — Rewards

- `src/effort/rewards.py` — catalogue in `data/rewards.json`, append-only
  ledger in `data/ledger.csv`. Both gitignored. A missing or corrupt file reads
  as empty or falls back to defaults rather than raising, so a bad file can
  never stop her seeing her balance.
- Catalogue edited through `st.data_editor` (add/remove rows), saved on a
  button press. Blank names are dropped and negative costs clamped on save.
- Balance is earned minus redeemed, floored at zero. Redeeming appends to the
  ledger and never touches points earned.
- Unaffordable rewards are greyed out with the shortfall spelled out
  ("60 points — 60 more to go") and a disabled button. **Verified** by writing a
  ledger that overspends the balance: all six rewards locked, balance clamped to
  0, zero exceptions.

## Phase 4 — Trends

- Points per week (line), minutes by category per week (stacked bar), and a
  day-of-week heatmap. Sidebar category filter scopes all three.
- `src/effort/theme.py` — the chart palette, with selected steps for light and
  dark rather than an automatic flip. Colour is pinned to the category, so
  filtering in the sidebar never repaints the categories that remain.
- Chart decisions worth knowing:
  - Straight line segments, not a smoothed curve — a curve through six weekly
    points invents mid-week values that were never measured.
  - `labelOverlap=False` on the heatmap and breakdown axes. Left alone, Vega
    dropped every other label and rows became unreadable.
  - The heatmap uses a fixed row height (`alt.Step`) so cells stay legible
    however many weeks there are.
  - Every chart has a "See the numbers" table, so nothing is colour-only.

## Phase 3 — This Week

- Total points, progress against an adjustable target (default 150), days
  logged, streak, both bonuses, category breakdown, and the delta vs last week.
- Friendly empty state when the week has nothing in it, which still shows last
  week's total and the current streak.
- "How points work" expander, generated from `POINTS_CONFIG`.
- The delta is green when ahead and **grey** when level or behind, never red.
  Mid-week she is nearly always behind last week's finished total, and the app
  should not tell a child off for it being Tuesday.

## Phase 2 — points engine + tests

- `src/effort/points.py`, with `POINTS_CONFIG` at the top of the module as
  specified. Everything downstream — engine, UI panel, README — reads from it.
- 33 tests, all passing. They cover the five required cases (the 60-minute cap,
  both bonuses, the Monday boundary, an empty week, a single row) plus the
  never-negative guarantee, the streak, and that a changed config actually
  changes both the points and the generated rules text.
- **Halves round up, not to even.** The brief said `round`, and Python's
  built-in rounds 2.5 to 2 — so 10 minutes at effort 2 would have earned 2
  points instead of 3. Losing a point to a rounding convention she has never
  heard of is indefensible, so `_round_half_up` is used and the rule is stated
  in the UI. Flag it if you disagree; it is one function.
- The daily cap applies per activity per day: two Maths sessions on one day
  share one 60-minute allowance, earlier session first. Case and spacing are
  ignored when deciding whether it's "the same activity".

## Phase 1 — loading + validation

**Setup**

- Installed `uv` (winget, `astral-sh.uv`) and pinned Python to 3.12 via
  `.python-version`. The first `uv init` resolved to 3.13 because
  `requires-python = ">=3.12"` permits it; the pin forces 3.12.14.
- Added streamlit, pandas, altair, and pytest (dev).
- `src/` layout. The project installs itself editable through `uv sync`
  (hatchling), so `import effort` resolves identically in the app and the
  tests without any `sys.path` juggling.

**Added**

- `data/sample_effort_log.csv` — 70 rows, six weeks ending Sat 2026-08-15.
  Generated with a seeded script (`scripts/generate_sample.py`) so it can be
  rebuilt identically. The file was *not* present in the repo despite the
  brief; this stands in until the real export arrives.
  - This week logs 4 distinct days across 3+ categories on purpose, so the
    category bonus is earned and the 5-day one is not — the This Week page
    will have something to nudge her about.
  - Last Tuesday has two Maths sessions totalling 85 minutes, so the
    60-minute cap is visible in the data and not only in the tests.
  - Six rows are deliberately broken, one per validation rule, so the
    problems panel always has something to show.
- `src/effort/config.py` — the data contract (columns, the eight categories,
  effort range, accepted date formats) and file locations. The *points* rules
  deliberately do not live here; they go at the top of the engine module.
- `src/effort/loading.py` — reads the CSV as plain text, interpreting nothing.
  Only whole-file failures raise `LogFileError` (missing, not UTF-8, no usable
  header); the app will catch that and show a panel. Tolerates a BOM from
  Excel, a missing `notes` column, extra columns, and blank spacer lines.
  Carries each row's real file line number so problems can point at it.
- `src/effort/validation.py` — splits the log into typed rows the engine can
  trust and a table of problems. A row can report more than one fault. Checks
  date, activity, category, minutes, and effort.
- `scripts/check_data.py` — prints load and validation results. How to see
  phase 1 working before there is any UI.
- `.gitignore` — ignores every CSV, then allows `data/sample_effort_log.csv`
  back in, then re-ignores `data/ledger.csv` and `data/rewards.json`. Verified
  with `git check-ignore`: a stray `data/her_real_log.csv` or `notes_export.csv`
  is not committable.

**Decisions**

- Unknown categories are set aside as problems, not coerced to `Other`, so a
  typo is visible rather than silently absorbed. One line in `validation.py`
  to flip.
- Dates are tried ISO-first, then day-first, so `07/08/2026` means 7 August.
  Verified against the sample.
- Minutes must be a whole number above 0 and at most 1440.
- Category matching ignores case and surrounding spaces; `maths` becomes
  `Maths` rather than becoming a problem.
